CRS CSS Module Split V1
Date: 2026-07-05

Purpose
-------

The earlier monolithic CSS file had grown to about 205 KB and more than 7700 lines.
It contained base styling, page-specific fixes, responsive fixes, PLC setup rules,
audit table fixes, phase control fixes, and final override blocks in one file.

This made future UI maintenance risky because a correction for one page could
accidentally affect another page.

Change Completed
----------------

The CSS has been split into smaller ordered modules under:

flask_app/static/css/modules/

The existing browser entry point remains:

flask_app/static/css/main.css

main.css now only imports the modules. Existing templates continue to load
main.css.

Current cache key in flask_app/templates/base.html:

css-v93-phase-scope-20260705

Important Design Rule
---------------------

The split is cascade-preserving.

This means:

- The module import order follows the same order as the earlier monolithic main.css.
- The module content was moved without semantic reordering.
- Visual appearance should remain the same after the split.
- Do not reorder imports unless all major screens are visually checked afterward.

Future CSS Work Rules
---------------------

1. Do not add new rules directly to main.css.
2. Add page-specific CSS to the nearest module.
3. If a new module is required, add it under flask_app/static/css/modules/.
4. Add the import to main.css only after deciding the correct cascade position.
5. Keep selectors page-scoped where possible, for example:

   .audit-history-workbench ...
   .stage-plc-rule-card ...
   .phase-master-table ...

6. Avoid broad selectors for table cells, buttons, and form controls unless it
   is a deliberate global design-system rule.
7. Do not add "final fix" blocks at the bottom unless it is temporary and
   documented with the target page and reason.
