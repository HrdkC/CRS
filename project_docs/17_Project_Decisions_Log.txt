PROJECT DECISIONS LOG
=====================

Decision 001
------------

Machine Ownership

Decision:

Machine belongs to one TBM Family.

Reason:

Physical machine identity is unique.

Examples:

P03 Family_A

Valid

P03 Family_B

Invalid

--------------------------------------------------

Decision 002
------------

Machine Code Standardization

Decision:

Machine codes are case-insensitive.

Examples:

P03 = p03

Reason:

Avoid duplicate machine records.

Decision 015
------------

Current Released Recipe Editing

Decision:

Current RELEASED recipe values are editable with audit.

Historical released versions remain locked and read-only.

Create Version remains available for major revisions, trial work, and controlled recipe development, but it is not mandatory for every small current-production adjustment.

Reason:

The system must help operators and reduce unnecessary operational burden while maintaining traceability.

Small production corrections should be possible directly on the current production version when authorized, validated, and audited.

Safety Rules:

- Only the current production released version can be edited.
- Historical released versions must not be edited.
- Min/max validation is mandatory.
- Old value and new value must be audited.
- User, timestamp, reason, machine, stage, and source must be captured.
- PLC upload overwrite must follow the same audit and historical-lock rules.
