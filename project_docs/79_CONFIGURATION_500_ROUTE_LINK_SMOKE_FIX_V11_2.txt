CRS V11.2 - Configuration 500 + Route/Link Smoke Fix
Date: 2026-07-17

ROOT CAUSE
The V11.1 Configuration Readiness patch used two names without importing them:
- quote from urllib.parse
- PLCRegistryManager from database.plc_registry_manager

Because /configuration calls _decorate_report() for every machine/stage, the missing
PLCRegistryManager import raised NameError and produced the CRS 500 page.
The stage detail page could also fail when building its PLC Create return URL because
quote was not imported.

FIX
1. Adds both missing imports to flask_app/routes/configuration_routes.py.
2. Adds scripts/check_crs_routes_and_links.py, a non-PLC safe verification tool.
3. The checker validates:
   - Python compilation
   - all Jinja template compilation
   - duplicate route/method collisions
   - all safe registered GET pages using database-backed sample IDs
   - rendered internal links
   - rendered form actions and HTTP method compatibility
4. It deliberately skips live PLC connection/identity verification routes and never
   starts a PLC download.

VALIDATION COMPLETED AGAINST V11 + V11.1
- Python files compiled: 356
- Jinja templates compiled: 62
- Route/method combinations checked: 151
- Safe GET results: 56 HTTP 200, 13 expected redirects, 1 expected synthetic-job 404
- Rendered links parsed: 2689

- /plcs/test_connection/<id>

- PLC download start/write operations
