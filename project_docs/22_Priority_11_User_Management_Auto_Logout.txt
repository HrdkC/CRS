# Priority 11 - User Management Completion + Auto Logout

## Goal
Complete plant-ready user management and session control for CRS.

## Final Roles
New users must use only these final CRS roles:

- ADMIN
- ENGINEERING
- TECHNOLOGY
- PRODUCTION
- OPERATOR

Legacy roles EDITOR and VIEWER remain supported only for old accounts until migration is complete.

## Role Hierarchy

ADMIN > ENGINEERING > TECHNOLOGY > PRODUCTION > OPERATOR

## Role Meaning

ADMIN:
- Super user
- Full access
- User management
- Session management
- System configuration
- Engineering/PLC/master configuration
- Backup/admin recovery

ENGINEERING:
- Technical engineering user below ADMIN
- Recipe view/download/edit/copy
- Submit review
- Approve/reject
- Engineering/PLC/master configuration access where routes support engineering capability
- Audit view where routes support audit capability
- No user management
- No active-session force logout
- No admin-only recovery functions

TECHNOLOGY:
- Recipe edit/copy
- Submit review
- Approve/reject
- Download
- No user management
- No admin configuration

PRODUCTION:
- Recipe edit/copy
- Submit review
- Download
- No approve/reject
- No user management

OPERATOR:
- View recipe
- Download released recipe
- No recipe editing
- No approval
- No admin/engineering configuration

## Required Default Users

The Priority 11 default-users helper creates/enables:

1. operator
   - Role: OPERATOR
   - Temporary password: operator123
   - Forced password reset: yes

2. engineering
   - Role: ENGINEERING
   - Temporary password: Engineering@123
   - Forced password reset: yes

3. hardik
   - Role: ADMIN
   - Purpose: backup super user
   - Temporary password: Hardik@123
   - Forced password reset: yes

The default primary admin user remains ADMIN. The hardik user is a backup ADMIN super user for recovery.

## Protected Super Users

The UI protects these accounts from disable/demote actions:

- admin
- hardik

The system also blocks disabling/demoting the last active ADMIN account.

## User Management Features Added

- Add User with final role selection
- Disable User
- Enable User
- Reset Password
- Require Password Change on Next Login
- Update User Role
- Default Operator User helper
- Default Engineering User helper
- Backup Admin User helper
- Combined default users helper
- User action audit events

## Auto Logout

Idle logged-in sessions are automatically logged out after:

CRS_SESSION_TIMEOUT_MINUTES environment variable, default 30 minutes.

Auto logout records:

- user_sessions.logout_time
- user_sessions.logout_reason = AUTO_LOGOUT
- user_sessions.auto_logged_out = 1
- audit_log action AUTO_LOGOUT

## Active Sessions

Active Sessions page now displays:

- username
- role
- login time
- last activity
- active minutes
- client IP
- workstation name
- force logout action

Only ADMIN can view and force logout active sessions.

## Completion Criteria

Priority 11 is complete when:

- Admin can create final-role users including ENGINEERING
- Backup ADMIN user hardik exists and can login after password change
- Engineering user exists and can login after password change
- Engineering is below ADMIN and cannot manage users or active sessions
- Admin can disable/enable normal users
- Admin can reset password and require reset
- Operator user exists and can login after password change
- Operator is restricted from admin pages
- Active session tracking works
- Auto logout works
- Audit log records user/session actions
